# TimeBloom — macOS Menu Bar Time Tracker

A polished, Harvest-style menu bar app for macOS 14 (Sonoma) that talks to
the **TimeBloom Suite Timer API** (Supabase edge function — full spec at
[`/openapi.json`](https://time-bloom-suite.lovable.app/openapi.json)).

The app lives **only** in the menu bar (no Dock icon), uses **SwiftUI**
for its popover UI, **AppKit** for the menu bar item, and **Swift
Concurrency (async/await)** for all networking. Tokens are stored
exclusively in the **Keychain**.

---

## 1. What the API gives us (and what it doesn't)

The Timer API is intentionally tiny — three endpoints:

| Endpoint                 | Purpose                                  |
|--------------------------|------------------------------------------|
| `GET  /?action=status`   | Is a timer running? Project, task, elapsed seconds. |
| `GET  /?action=projects` | Active projects + their tasks.           |
| `POST /` body `{action}` | `start` / `stop` / `switch`.             |

Auth is Supabase JWT (1 h access token + refresh token). Documented
business rules we honour in the UI:

- **One timer at a time.** Trying to `start` while running → `409`. The
  popover offers **Switch** instead.
- **`switch` < 60 s reassigns** the existing entry (no minutes logged).
  ≥ 60 s logs the elapsed minutes and starts a new entry.
- **Minimum logged duration 1 minute.** Quick mistakes still register.
- **No `create task` endpoint.** Tasks must already exist on the web
  app — the picker only chooses from them. (Filed under "future API
  work" below.)
- **No backdated stop.** The API records minutes from start to *now*,
  so the idle-detection dialog can't truly "discard" idle minutes —
  it can only **stop now**, **switch task**, or **keep**. We tell the
  user this honestly inside the dialog.

## 3. Create the Xcode Project

The repo holds **only the Swift source files, Info.plist, and
entitlements**. The `.xcodeproj` package is generated by Xcode itself;
hand-editing the project file format is fragile, so we let Xcode own
it. Follow these steps once:

1. **File → New → Project…** → macOS → **App** → Next
2. Settings:
   - **Product Name:** `TimeBloom`
   - **Team:** your Apple ID
   - **Organization Identifier:** `app.timebloom` (or your own)
   - **Bundle Identifier:** `app.timebloom.menubar`
   - **Interface:** SwiftUI
   - **Language:** Swift
   - **Storage:** None
   - Uncheck **Include Tests** for now (you can add a test target later)
3. Save the project at the **root of this repo** so the generated
   `TimeBloom.xcodeproj` sits next to the existing `TimeBloom/` folder.
4. **Delete** Xcode's auto-generated `ContentView.swift`,
   `TimeBloomApp.swift`, `Assets.xcassets`, and the auto-generated
   `Info.plist` (we ship our own).
5. **Right-click the `TimeBloom` group → Add Files to "TimeBloom"…**
   and add the entire existing `TimeBloom/` folder. Choose
   **"Create groups"** (not folder references).
6. In the target's **General** tab:
   - Set **Minimum Deployments → macOS 14.0**.
7. In the target's **Info** tab:
   - Either delete the default `Info.plist` reference and point
     `INFOPLIST_FILE` at `TimeBloom/Resources/Info.plist`, **or** copy
     these keys into the auto-generated plist:
     - `Application is agent (UIElement)` → `YES` (= `LSUIElement`)
     - Notifications usage description (any short string)
8. In the target's **Signing & Capabilities** tab:
   - Tick **App Sandbox** → enable **Outgoing Connections (Client)**.
     (This generates an entitlements file for you — replace it with the
     `TimeBloom/TimeBloom.entitlements` shipped in this repo, or just
     copy the keys across.)
   - Add the **User Notifications** capability (Sonoma includes the
     framework but the capability ensures it's linked).
9. **Open `TimeBloom/Configuration.swift`** and set
   `supabaseAnonKey` to the **anon public** key from your Supabase
   dashboard (`Project Settings → API`). The URL is already the
   correct project URL from the OpenAPI spec.
10. Hit ⌘R. The leaf icon should appear in your menu bar.

## 5. Configuration

Everything you might need to change is in **`Configuration.swift`**:

```swift
static let supabaseURL     = URL(string: "https://cxgaxguhugxdbrrgqqcj.supabase.co")!
static let supabaseAnonKey = "REPLACE_WITH_YOUR_SUPABASE_ANON_KEY"
```

The anon key is **safe to embed in the client** — Supabase RLS policies
gate the actual data access by user JWT.

User-tunable preferences live in `AppSettings.swift` (currently exposed
only programmatically — a Settings window is the obvious next addition):

| Setting                  | Default | Effect                                  |
|--------------------------|---------|-----------------------------------------|
| `idleThresholdMinutes`   | 5       | Trigger idle dialog after this long.    |
| `longRunningTimerHours`  | 4       | Trigger long-running notification then. |
| `notifyOnAutoStop`       | true    | Banner when the server reports a stop.  |

## 6. How to Test Each Feature

Run the app from Xcode (⌘R) with the debugger attached. The menu bar
icon is a leaf — outline when stopped, filled when running.

| Feature                | How to verify                                                    |
|------------------------|------------------------------------------------------------------|
| **Login**              | First launch shows email/password form. Successful sign-in flips to TimerView; tokens land in Keychain (verify with `Keychain Access.app → "app.timebloom.menubar"`). |
| **Token refresh**      | In Xcode, set a breakpoint in `AuthService.performRefresh`. Wait > 1 hour, click any button — breakpoint fires, refresh round-trips silently. |
| **Start / Stop**       | Click leaf → "Start a timer" → pick project → leaf fills, elapsed ticks. Click "Stop" → leaf empties, server logs minutes (verify in web app). |
| **Switch (< 60 s)**    | Start a timer, immediately switch project. Server returns `{action: "reassigned"}` — no time logged. |
| **Switch (≥ 60 s)**    | Same flow after a minute → server returns `{action: "switched", logged_minutes: N}`. |
| **One-timer rule**     | Start one timer in the web app, then click Start in the menu bar app. The 409 error surfaces as a banner inviting you to switch instead. |
| **Background sync**    | Start a timer in the web app; within 30 s the menu bar icon fills automatically (poll). |
| **Idle detection**     | In `AppSettings.swift` temporarily set `idleThresholdMinutes = 1`. Don't touch your Mac for a minute → floating dialog appears. |
| **Long-running alert** | Temporarily set `longRunningTimerHours = 0` and start a timer → notification fires within 1 s of the next tick. Restore to 4 afterwards. |
| **Notifications**      | Make sure System Settings → Notifications → TimeBloom is set to **Banners** + **Allow notifications**. |
| **Quit**               | Right-click the leaf → Quit. Or `kill -9` from Terminal during dev — the popover doesn't get in the way. |

To poke the API directly while debugging:

```bash
# Replace TOKEN with the access_token you printed from the debugger:
curl -H "apikey: $ANON_KEY" \
     -H "Authorization: Bearer $TOKEN" \
     'https://cxgaxguhugxdbrrgqqcj.supabase.co/functions/v1/timer-api/?action=status'
```

## 7. Architectural Notes

**Why an `AppDelegate` if SwiftUI has `MenuBarExtra`?** `MenuBarExtra`
on macOS 14 doesn't expose programmatic show/hide of the popover (we
need this for the "Switch task" notification action), nor full control
over the icon swap. AppKit gives us both, and SwiftUI handles the
content as usual via `NSHostingController`.

**Why an `actor` for `APIClient`?** Concurrent timer-status polling
and a manual button tap can both touch the request pipeline. Wrapping
`URLSession` in an actor serialises the auth-refresh-and-retry handshake
without locking other call sites.

**Why Observation, not Combine?** Observation (`@Observable`) is the
macOS 14 native pattern. SwiftUI views observe stored properties
without `@Published` boilerplate, and `withObservationTracking` lets
the AppKit shell react to changes without subscribing to publishers.

**Why poll instead of a websocket?** The API doesn't expose one. A 30 s
poll is cheap and keeps the implementation simple. If/when Supabase
realtime is exposed for timers, swap `TimerStore.refreshTask` for a
realtime subscription.

## 8. Where the Spec Drives the Code

Specific endpoint references inside the source:

- `Models/Models.swift` — `TimerStatus` decodes the `oneOf` from
  `GET /?action=status`. `TimerActionResponse` decodes all four
  documented response shapes for `POST /`.
- `Networking/APIClient.swift::fetchStatus` → `GET /?action=status`.
- `Networking/APIClient.swift::fetchProjects` → `GET /?action=projects`.
- `Networking/APIClient.swift::perform` → `POST /` with `TimerAction`.
- `Networking/APIClient.swift::send` translates the documented status
  codes (401/403/404/409) into typed `APIError` cases.
- `Networking/SupabaseAuthClient.swift` posts to
  `/auth/v1/token?grant_type=password|refresh_token` per the
  `x-authentication` block of the spec.

## 9. Suggested Next Steps

These would make the app genuinely great but are out of scope for v1:

1. **Settings window** — surface `idleThresholdMinutes`,
   `longRunningTimerHours`, and login/logout in a real `Settings` scene.
   The empty `Settings { EmptyView() }` in `TimeBloomApp.swift` is the
   slot waiting for it.
2. **Global hotkey to start/stop** (e.g. ⌃⌥⌘T). Use `MASShortcut` or
   the new `KeyboardShortcuts` Swift package.
3. **Recent projects pinned to top of the picker.** The API doesn't
   expose recency, so cache locally.
4. **Login at System startup** via `SMAppService.loginItem`.
5. **Today's logged time summary** in the popover footer — would need
   the API to grow a `summary` endpoint.
6. **Realtime sync** if/when Supabase exposes a Realtime channel for
   the timers table — replace polling.
7. **Per-project colour chips** if the API grows a `color` field on
   `Project`.
8. **Task creation from the picker** if the API grows a `POST /tasks`
   endpoint.
9. **Apple-flavoured menu bar animation** — subtle pulsing dot in the
   icon while running. `NSStatusItem.button.image` swapped on a
   `CADisplayLink` is the pattern.
10. **Crash & telemetry** via `os.signpost` and `MetricKit`.
